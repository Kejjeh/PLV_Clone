# Weather / temperature study — SP starts (BrownU 8-team points)

## Collection (honest n)

- **Endpoint:** `https://statsapi.mlb.com/api/v1.1/game/{game_pk}/feed/live`
  → `gameData.weather` = {condition, temp °F, wind}, `gameData.venue.name`.
  Pulled via python `urllib` (Bash background job, 0.10s sleep between calls,
  incremental 250-row flush to CSV). Collection path fully reproducible:
  `python scripts/_oneoff/weather_study.py --collect`.
- **Collected 7,243 / 7,283 distinct game_pks (99.5%)** across 2023-2025 — i.e.
  the full universe of games that contain a qualifying SP start, not just a
  sample. **Zero collection failures of consequence** (2 dome games returned
  `temp=0`; <40°F rows = 23, all real cold games).
- Cache: `data/research/xfp_cache/game_weather_sample.csv` (game_pk, condition,
  temp, wind, venue, venue_id).
- **Starts panel:** per-(pitcher, game_pk) starts with ≥9 outs, FP from statcast
  events (matches `build_historical_panel.build_pitcher_actuals_statcast` grain),
  ER ≈ 0.92×runs. **n = 13,595 starts with weather** (11,219 after removing
  dome/roof-closed games).
- Temp range 0-103°F (outdoor 30-103), mean **73.1°F**. Conditions: Partly Cloudy
  2195, Clear 1447, **Roof Closed 1099 + Dome 165** (controlled ~72°F — these
  damp the temp signal, so an OUTDOOR-only cut is reported alongside ALL).

## (A) Does temperature predict SP start performance?

Pearson correlations, temp vs per-start outcome:

| Pair | ALL (n=13,595) | OUTDOOR only (n=11,219) |
|---|---|---|
| temp ↔ SP **FP/start** | **−0.0444** | **−0.0468** |
| temp ↔ mean **velo** | +0.0290 | +0.0418 |
| temp ↔ **K** | −0.0277 | — |
| temp ↔ **H** allowed | +0.0602 | +0.0592 |
| temp ↔ **ER** allowed | +0.0621 | +0.0669 |

**By temp bucket (ALL):**

```
tbucket     n      fp    velo      k      h     er
<50       380  11.27  88.30  5.21  4.77  2.15
50-60    1125  11.41  88.47  5.03  4.90  2.19
60-70    2946  11.49  88.77  5.10  4.93  2.26
70-80    5981  11.13  88.85  5.09  5.06  2.38
80+      3159  10.27  88.75  4.91  5.24  2.53
```

- **Direction is exactly as theorized but the effect is small.** Hotter games →
  more offense (H, ER both rise monotonically with temp), fewer SP K, and lower
  SP FP. The 80+°F bucket SP averages **10.27 FP** vs **11.4-11.5 FP** in the
  50-70°F band — a real ~1.2 FP/start hot-weather penalty at the tail, but the
  linear correlation is only **r ≈ −0.047** (temp explains ~0.2% of FP variance).
- **Coors Field is the dominant venue effect, not ambient temp:** 443 Coors
  starts average **8.20 FP vs 11.13 non-Coors** (−2.9 FP/start), at a normal
  75.6°F mean temp. Altitude/park >> temperature.
- temp ↔ velo is **positive but negligible** (+0.03 to +0.04): warmer air, very
  slightly higher readings. Not a usable predictor on its own.

## (B) De-confound: does temp explain the early-season velo dip, and does cleaning it sharpen the velo-drop→bust flag?

Method: per pitcher-year, `velo_drop = velo_game − own-season-mean velo`
(negative = a dip below the pitcher's own baseline — the quantity the in-season
velo flag keys on). Residualize velo on temp within pitcher-year, recompute the
temp-adjusted drop, and compare the velo-drop→bust relationship raw vs adjusted.

**Cold games DO depress velo (confound confirmed, but small):**
- Within-pitcher-year, velo vs temp slope = **+0.0072 mph/°F** (ALL) /
  **+0.0080** (outdoor), r ≈ +0.07 to +0.08.
  → a 30°F-colder game costs only **~0.22-0.24 mph** off a start's mean velo.
- **April starts** sit **−0.154 mph** below own-season velo (n=2,275) vs
  **+0.031** for non-April, at April mean **63°F vs 75°F**.
- After temp-adjustment, the April dip shrinks to **−0.097 mph** →
  **temp explains ~37% (ALL) / ~44% (outdoor) of the early-season velo dip.**
  So the cold-April warmup confound is **real and partly temperature-driven.**

**BUT the velo-drop → bust signal does NOT strengthen when you clean it:**

| Metric | RAW velo-drop | TEMP-ADJUSTED velo-drop |
|---|---|---|
| velo_drop ↔ FP (Pearson) | +0.0339 | +0.0372 |
| Bust rate (FP<5), biggest-drop quintile | 0.282 | 0.282 |
| Bust rate, rest | 0.245 | 0.245 |
| **Quintile gap** | **+0.037** | **+0.037** |

- The biggest-velo-drop quintile busts at **28.2% vs 24.5%** for the rest — a
  weak but present signal (gap +3.7pp). After removing the cold-game velo
  component, the gap is **identical (+0.037)** and the FP correlation barely
  moves (+0.034 → +0.037). The velo-drop→bust flag is **unchanged**, not
  sharpened, by temp de-confounding.
- **Why:** temp accounts for only ~0.24 mph of a 30°F swing. The velo dips that
  actually predict busts are **much larger than the thermal component** (fatigue,
  injury, mechanical), so scrubbing the small cold-game piece leaves the
  predictive structure essentially intact. The confound is real for the *level*
  of an April reading but is too small to matter for the *bust classification*.

## Verdict — RESEARCH-ONLY

**(A) Weather is NOT worth collecting at scale for the SP model.** Temperature
moves SP outcomes in the expected direction (hot → +H/+ER/−FP, ~1.2 FP penalty
in the 80+°F tail) but the linear signal is r ≈ −0.05 (≈0.2% of variance) and is
dwarfed by the park effect already captured elsewhere (Coors −2.9 FP/start is
~25× the ambient-temp tail effect). rp3 already encodes park/opponent context
(`ros_park_pf_HR_weighted`, `ros_opp_xwoba_weighted`); a raw game-temp feature
would be a thin, redundant add and is not eligible for a `/validate-feature` run
against the full RP3_FEATS baseline. The one place temp has standalone value is
**daily streaming color** (a hot-day Coors/Texas start is a mild bench-tilt), not
a ranker term.

**(B) Temp does NOT de-confound the velo-drop flag.** Cold April games genuinely
depress velo (~0.24 mph/30°F, explaining ~40% of the April-vs-season dip), so the
confound is real — but it is too small to change the velo-drop→bust
classification (quintile bust gap +0.037 raw and temp-adjusted alike). **We do
not need to temperature-adjust in-season velo for the bust flag.** The warmup
confound in the velo work, if it bites, is driven by per-pitcher early-season
ramp / arm-readiness, not by ambient game temperature — that is the lever to
pursue, not weather.

**Net:** honest, well-powered (n≈13.6k starts, 99.5% game coverage), and both
goals answered NO. Weather data path is documented and cached should a future
streaming-color use-case want it, but it is not promoted to any model.
