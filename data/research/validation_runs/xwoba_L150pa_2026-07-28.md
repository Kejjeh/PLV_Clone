# xwoba_L150pa — rh3 candidate feature validation

## Provenance

Follow-up to `rolling_xwoba_windows_2026-07-28.md`, which measured this window at
partial r **+0.062 [+0.035, +0.084]** on forward-14d FP/g, controlling for
[un-shrunk season-to-date xwOBA, shrunk FP level, playing time], 7,657 anchors /
575 hitters / 6 seasons. That study explicitly did **not** run Rule 9.

## Why the prior number is expected to shrink

1. rh3 already carries **`xwoba_per_pa_to_sh`** — season-to-date xwOBA per PA shrunk
   with K=300 PA (`SHRINK_SPEC_TO`). The prior study controlled on the **un-shrunk**
   season xwOBA, a weaker control than what production actually uses.
2. rh3 also carries `k_pct_to_sh`, `bb_pct_to_sh`, `barrel_pct_to_sh`,
   `hard_hit_pct_to_sh`, `iso_to_sh` — jointly these reconstruct much of what full
   xwOBA measures. The same algebraic-redundancy argument killed
   `xwoba_on_contact_to_sh` (rh3, 2026-05-25) and `xwoba_contact_to` (rp3).
3. rh3 carries `prior_fp_per_pa` (Marcel), which absorbs the prior-season
   information the `_cross` variant would import.
4. The prior study's target was forward-14d FP/g; rh3's target is
   **rest-of-season** FP/PA — a longer, more mean-reverting horizon where a
   150-PA window's recency advantage should decay.

## Baseline (Rule 9) — the FULL production feature list, 21 features

From `RH3_FEATS` in `src/plv_clone/models/xfp/rh3.py`:

```
iso_to_sh, k_pct_to_sh, hr_per_pa_to_sh, hard_hit_pct_to_sh, contact_pct_to_sh,
whiff_pct_to_sh, swstr_pct_to_sh, bb_pct_to_sh, chase_pct_to_sh, in_play_pct_to_sh,
sb_per_pa_to_sh, xwoba_per_pa_to_sh, barrel_pct_to_sh, prior_fp_per_pa, prior_pa_eff,
pa_to, split_day, lift_h2_aug150, xwoba_residual_career, career_stage,
ros_opp_sp_xwoba_weighted
```

No curated subset. Gate = `cross_year_eval` (LOO ridge over
TRAIN_YEARS=[2018,2019,2021,2022,2023,2024,2025], RidgeCV alphas 1e-1..1e5, cv=5),
identical to production.

## Matched-sample requirement (declared in advance)

`cross_year_eval` drops rows with any NaN feature. Adding a feature that is NaN
early in the season would silently shrink the evaluation frame, making
baseline-vs-extended non-comparable. **Both** the baseline and the extended model
are therefore evaluated on the SAME frame — rows where the candidate is non-null —
and the baseline r is re-measured on that restricted frame, not carried over from
the full frame.

## Step 2.5 — data-coverage pre-check

- `estimated_woba_using_speedangle` / `woba_value` / `woba_denom`: Statcast **2015+**.
  Verified present in `statcast_2018..2026.parquet`.
- Signal needs no year-over-year lookback (`_within`); `_cross` needs at most one
  prior season, available for every training year ≥2019 (2018 rows fall back to
  within-season availability).
- Training-eligible cohorts: 2018, 2019, 2021, 2022, 2023 (5) + holdout 2024, 2025.
  Rule 2(b) needs ≥5 of 7 → **satisfiable**. Rule 5 needs ≥30 hitter-years/year;
  rolling frame carries ~1,300 qualifying rows/year → satisfiable.
- **PASSES pre-check.** Proceed to Step 3.

## Sweep context (Rule 3)

Two pre-registered variants (`_within`, `_cross`). N=2, so the Bonferroni-adjusted
bar is α/2. With a hard effect-size gate of +0.005 cross-year r this is not a
grid sweep and the correction is not load-bearing — but if exactly one of the two
variants passes, it is to be treated with the skepticism Rule 3 prescribes.

## Gates

| Gate | Bar |
|---|---|
| (a) Effect size | Δ cross-year r ≥ **+0.005** vs full baseline (production gate) |
| (b) Year consistency | Δr sign consistent in ≥5 of 7 LOO years |
| (c) Holdout | Δr > 0 with correct sign on BOTH 2024 and 2025 |
| Rule 8 | Convergence curve across split_day; same sign at most cutoffs |

# RESULTS (run 2026-07-28)

## Data integrity checks

- **Join sanity:** `corr(n_pa_season_at_cut, pa_to) = 0.9999`, mean abs diff 2.2 PA.
  The residual gap is expected — `pa_to` counts sac bunts / catcher's interference,
  which `woba_denom==1` excludes. Cutoff alignment confirmed.
- **Coverage on the eligible frame (n=38,704):** `_within` 24,706 (63.8%),
  `_cross` 36,900 (95.3%).
- `_within` coverage by `split_day` (%): 30→0, 37→2, 44→26, 51→43, 58→54, 65→62,
  72→67, 79→72, 86→76, 93→79, 100→81, …, 170→100. A within-season 150-PA window
  simply does not exist before ~day 44.
- **Baseline completeness:** 22/22. The live `RH3_FEATS` imported from
  `plv_clone.models.xfp.rh3` has **22** features; the hardcoded copy in the older
  breakout-signal harness has 21 (missing `bx_prior_h`, promoted 2026-07-10).
  The script aborts if any baseline feature is absent — it fired, and `bx_prior_h`
  was wired in before results were read.

## The matched-sample correction actually mattered

| Frame | Baseline cross-year r | n |
|---|---|---|
| Full frame (reference only) | 0.6418 | 36,571 |
| `_within` matched frame | **0.6641** | 23,592 |
| `_cross` matched frame | **0.6487** | 34,841 |

Restricting to rows where a 150-PA window exists removes thin-sample hitters, who
are the hardest to project — so the baseline r rises by **+0.022** on the `_within`
frame for reasons that have nothing to do with the candidate. Comparing the extended
model on the matched frame (0.6648) against the full-frame baseline (0.6418) would
have reported **+0.0230** instead of the true **+0.0007** — a **33× over-claim**, and
the same shape of error as the 2026-05-13 rh3/rp3 v2 incident. Pre-registering the
matched-frame requirement is what caught it.

## Gate results

| | `_within` | `_cross` |
|---|---|---|
| baseline r (matched) | 0.6641 | 0.6487 |
| extended r | 0.6648 | 0.6506 |
| **Δ cross-year r** | **+0.0007** | **+0.0019** |
| (a) ≥ +0.005 | **FAIL** | **FAIL** |
| (b) sign consistency | 6/7 PASS | 6/7 PASS |
| (c) holdout 2024 / 2025 | +0.0011 / +0.0010 PASS | +0.0020 / +0.0016 PASS |
| n (matched rows) | 43,172 | 69,563 |

Per-year Δr `_cross`: 2018 +0.0015, 2019 +0.0020, 2021 +0.0031, 2022 **−0.0005**,
2023 +0.0026, 2024 +0.0020, 2025 +0.0016. (2022 is the same season that came in at
+0.003 in the marginal study — consistently the null year.)

The direction is right and remarkably stable; the **magnitude is 2.6–7× below the
gate**. This is a clean sub-gate result, not a noisy one.

## Rule 8 — convergence curve (`_cross`, TRAIN_ONLY years)

| split_day | 30 | 37 | 44 | 51 | 58 | 65 | 72 | 79 | 86 | 93 |
|---|---|---|---|---|---|---|---|---|---|---|
| Δr | +.0041 | +.0022 | +.0032 | +.0014 | +.0025 | +.0026 | +.0006 | +.0002 | +.0004 | +.0005 |

| split_day | 100 | 107 | 114 | 121 | 128 | 135 | 142 | 149 | 156 |
|---|---|---|---|---|---|---|---|---|---|
| Δr | −.0001 | +.0006 | −.0008 | +.0005 | +.0017 | +.0009 | +.0002 | −.0014 | −.0001 |

15/19 cutoffs positive, median **+0.0006**. Sign is stable enough to pass Rule 8 on
consistency, but the shape is the whole story: **the lift is concentrated early
(day 30: +0.0041, the largest value anywhere) and decays to ~0 by day 72**, going
mildly negative late. A fixed-PA window is only useful while the season-to-date
sample is thin — and `xwoba_per_pa_to_sh` is already shrunk with K=300 PA, which is
precisely the thin-sample insurance the rolling window would otherwise provide.
No cutoff anywhere reaches the +0.005 gate.

## Rule 4 / redundancy diagnostic — why it failed

Regressing the candidate on the 22 baseline features:

| | reconstructible R² | marginal r vs target | r of UNIQUE residual vs target |
|---|---|---|---|
| `_within` | **0.735** | +0.427 | +0.030 |
| `_cross` | **0.738** | +0.431 | +0.048 |

**The signal is real and strong — and almost entirely already in the model.** The
candidate correlates +0.43 with rest-of-season FP/PA on its own, but ~74% of it is
linearly reconstructible from features rh3 already carries, and what remains carries
only +0.03–0.05. This is the redundancy hypothesis pre-registered in reason (2),
confirmed empirically — the same signature that rejected `xwoba_on_contact_to_sh`
(rh3, 2026-05-25) and `xwoba_contact_to` (rp3).

The failure mode is **redundancy, not absence of signal.** A component-level retest
(Rule 4) is therefore not indicated: Rule 4 exists for signals buried by composite
noise, and this signal is not buried — it is already counted.

## Reconciliation with the +0.062 partial r from the marginal study

Both numbers are correct; they answer different questions.

| | marginal study | this run |
|---|---|---|
| control | un-shrunk season xwOBA + FP level + PT (3 terms) | full 22-feature production model |
| target | forward **14-day** FP/g | **rest-of-season** FP/PA |
| result | partial r +0.062 | Δ cross-year r +0.0019 |

Three of the four pre-registered shrink reasons are visible in the data: the
production control is much stronger (74% reconstruction), the RoS horizon is longer
and more mean-reverting than 14 days, and `prior_fp_per_pa` + `bx_prior_h` absorb the
prior-season information the `_cross` variant imports. The earlier study was not
wrong — it was measuring against a weaker baseline, which is exactly what Rule 9
exists to prevent us from shipping on.

## VERDICT: MARGINAL — do NOT promote

Δ cross-year r **+0.0019** (best variant) against the full production baseline,
versus a **+0.005** gate. Sign-consistent (6/7) and holdout-positive (2/2), so it is
a genuine-but-tiny positive rather than a null — hence MARGINAL rather than REJECTED.
`scripts/xfp/xfp_rh3_pipeline.py` and `RH3_FEATS` are unchanged.

**Do not re-test this window against rh3 without new data.** The binding constraint
is redundancy with `xwoba_per_pa_to_sh` + the shrunk rate stack, which will not change
as TRAIN_YEARS grows. A re-test only becomes interesting if `xwoba_per_pa_to_sh` is
ever removed or its K=300 shrinkage is re-tuned.

**Where the window may still legitimately be used:** as a display/context lens only
(Rule 13), which is already its status — `current_l150_xwoba` and `career_percentile`
ship in `batter_rolling_features.csv` and are consumed by `/roster-deep-audit` and
`league_wide_full_audit.py`. This run does not disturb that; it establishes only that
the window must not become a ranker input.

## Incidental findings (not part of this validation)

1. **`scripts/xfp/research/validate_rh3_breakout_signals.py` has a broken `ROOT`.**
   It sets `ROOT = Path(__file__).resolve().parents[2]`, which resolves to
   `plv_clone/scripts/` — the file lives one level deeper than when that line was
   written. All three of its optional baseline inputs (`seasonality_h2_locked.csv`,
   `hitter_xwoba_residual.csv`, `ros_opp_sp_xwoba_per_hitter.csv`) therefore
   `.exists() == False` and are filled with **0.0**, so any sweep run through it
   after the file moved was measured against a baseline with **three constant
   features** — an inflated-lift risk of exactly the kind Rule 9 forbids. This run
   overrides those paths explicitly and asserts existence. **The harness itself is
   not fixed here**, and past verdicts produced by it are worth re-checking.
2. **That harness's hardcoded `RH3_FEATS` is stale** (21 features; production has 22
   since `bx_prior_h` was promoted 2026-07-10). Any future rh3 candidate run should
   import the list from `plv_clone.models.xfp.rh3` rather than copy it.
